# KOReader for iOS / iPadOS — Project Spec

Status: living document, last updated 2026-10-28.

This fork (`parkerbk/koreader-ios`, based on `hezi/koreader-ios`) ships
KOReader as a sideloadable iOS / iPadOS app. It tracks upstream
`koreader/koreader` and keeps iOS changes small and isolated so rebases
stay cheap. Build instructions live in [`Building_iOS.md`](Building_iOS.md);
this document covers *what* the port does, how it is structured, and
what is planned next.

## 1. Goals and non-goals

Goals:

- Run upstream KOReader unmodified wherever possible, on iPhone and iPad,
  as a personal sideloaded build (Xcode free team or paid account).
- Feel native enough to use daily: full-screen, notch/home-indicator
  aware, correct touch input, survives backgrounding, opens files from
  the Files app and cloud providers.
- Ship a curated set of plugins inside the bundle, and let the user add
  plugins, fonts, and patches at runtime through Storefront or by
  dropping files into Documents with the Files app.
- Support every current iPhone form factor, including the foldable
  **iPhone Duo** (see §6).

Non-goals:

- App Store distribution. KOReader's GPL licence and its runtime
  plugin/code loading are both incompatible with App Store review.
- iOS Simulator builds. `base/` libraries are built device-only
  (`SUPPORTED_PLATFORMS: iphoneos`, `arm64`).
- Native (UIKit) reimplementation of KOReader's UI. The UI stays the
  SDL3-rendered Lua UI from upstream.

## 2. Architecture

```
UIApplicationMain (SDL3)
  └─ SDL_main  = platform/ios/ios_loader.m
       ├─ chdir(<bundle>/app)            # Lua tree, fonts, resources
       ├─ env: KO_IOS=1, KO_HOME=<Documents>, SDL_FULLSCREEN=1,
       │       SDL_TOUCH_MOUSE_EVENTS=0, LC_ALL
       ├─ mkdir <Documents>/plugins, <Documents>/fonts
       ├─ copy app/seed/plugins/* → <Documents>/plugins (only if missing)
       └─ luaL_dofile("reader.lua")      # upstream entry point
```

KOReader identifies as the SDL device (`frontend/device/sdl/device.lua`).
iOS-specific behaviour is gated on `os.getenv("KO_IOS") == "1"`, not on a
new device class, to keep the diff against upstream small.

| Area | Where | Notes |
|---|---|---|
| Launcher | `platform/ios/ios_loader.m` | Resolves paths via `NSBundle`; assets live in `app/` because `KOReader` (executable) and `koreader/` would collide on case-insensitive APFS. |
| Native bridges | `platform/ios/ios_filepicker.m` | Document picker, security-scoped bookmarks, `ko_ios_get_safe_area_pixels`. Called from Lua via FFI. |
| Xcode project | `platform/ios/project.yml` (XcodeGen) | Regenerated by `make TARGET=ios xcodeproj`. Pre-build runs `make TARGET=ios all`; post-build runs `embed-bundle-payload.sh`. |
| Bundling | `platform/ios/do_ios_bundle.sh`, `embed-bundle-payload.sh`, `make/ios.mk` | Copies the staging tree and dylibs into `KOReader.app/app`. |
| Lua precompile | `platform/ios/precompile-lua.sh` | Converts bundled `.lua` to LuaJIT bytecode with the host LuaJIT, which cuts cold launch time by 30–50%. |
| Prereq check | `platform/ios/check-prereqs.sh` | Fails early on missing Xcode/Homebrew tools. |
| Base | `base/` → `hezi/koreader-base-ios` | iOS make target, monolibtic build, thirdparty patches, SDL3 safe area + lifecycle, night-mode invert, `runInSubProcess` inline fallback. |
| Plugins | `plugins/iosfilepicker.koplugin` | Bundled, read-only. |
| Seed plugins | `platform/ios/seed/plugins/` | Copied into the writable `Documents/plugins` on first launch (Storefront, see §5). |

### 2.1 Sandbox constraints and how they are handled

- **No `fork()`** — `util.runInSubProcess` falls back to running the
  function inline (base). Anything upstream does "in the background"
  runs on the UI thread on iOS and can stall the UI.
- **Read-only bundle** — `KOReader.app` is signed and immutable. User
  data, settings, and user plugins go to `KO_HOME` = the app's
  `Documents/` folder. `UIFileSharingEnabled` exposes that folder in
  Files → On My iPhone → KOReader.
- **No unsigned native code** — dylibs/`.so` not in the signed bundle
  cannot be loaded. Plugins that ship native libraries only work if they
  are vendored at build time.
- **Cloud files** — accessed via `UIDocumentPickerViewController`, then
  persisted as security-scoped bookmarks and re-resolved at launch.

## 3. Display and input

- **Full screen**: `SDL_FULLSCREEN=1` sizes the SDL window to the current
  display mode; the status bar is hidden; `UIRequiresFullScreen` is set.
- **Safe area**: `SDL3.applyIOSSafeArea` reads `UIWindow.safeAreaInsets`
  (in pixels via `nativeScale`) and shrinks `S.w/S.h`. The blitbuffer is
  rendered into an inset sub-rect, and the bezel is painted white, or
  black in night mode. Touches in the bezel clamp to the nearest edge.
  The insets are re-queried on every `framebuffer:resize`.
- **Touch**: real finger events only (`SDL_TOUCH_MOUSE_EVENTS=0`) to
  avoid double taps. `hasKeyboard` is false on iOS so menus don't draw
  per-item shortcut letters.
- **Keyboard**: the iOS system keyboard, not KOReader's VirtualKeyboard
  (`Device:hasSystemKeyboard()` → `Device:hidesVirtualKeyboard()`).
  Focused `InputText`s report their rect through
  `Device:setTextInputArea` (`SDL_SetTextInputArea`), so SDL slides the
  view up only when the keyboard would cover the field.
- **Clipboard**: SDL's clipboard, which is `UIPasteboard` on iOS, so
  KOReader's copy and paste share the system clipboard.
- **Rotation**: the SDL window is resizable, so SDL allows every
  orientation in Info.plist and resizes the window on rotation;
  `WINDOW_RESIZED` re-lays out KOReader (see §6 for the pixel/point
  caveat). KOReader's own rotation setting rotates the content inside
  the window and shouldn't be combined with device rotation.
- **Night mode**: blitbuffer stays non-inverted; `_render` XOR-inverts the
  dirty region into a scratch buffer right before the texture upload.
- **Orientation**: iPhone allows portrait + both landscapes; iPad allows
  all four (Info.plist).
- **Lifecycle**: SDL foreground/background/low-memory events are
  forwarded as `EV_SDL`; on `DID_ENTER_FOREGROUND` the device forces a
  full repaint.

## 4. Files and storage

| Path | Contents |
|---|---|
| `KOReader.app/app/` | Read-only Lua tree, resources, built-in fonts, bundled plugins, dylibs (`app/libs`), first-run seeds (`app/seed/`). |
| `Documents/` (`KO_HOME`) | `settings.reader.lua`, `settings/`, history, cache, books. |
| `Documents/plugins/` | User plugins: Storefront itself, anything it installs, and anything copied in through the Files app. Scanned by `PluginLoader` after the bundled `plugins/`. |
| `Documents/fonts/` | User fonts: Storefront installs and `.ttf`/`.otf` dropped in through the Files app. On iOS, `ui/elements/font_settings.lua` returns this as the user font dir, so `fontlist` picks it up. There are no readable system font dirs. |
| `Documents/patches/` | User patches (Storefront's Patches tab), loaded by upstream's patch loader. |
| Security-scoped bookmarks | Saved by `iosfilepicker.koplugin`, resolved at launch. |

Everything under `Documents/` shows up in Files → On My iPhone/iPad →
KOReader.

## 5. Storefront plugin

[Storefront](https://github.com/ultimatejimmy/storefront.koplugin) lets the
user browse, install, and update KOReader plugins, user patches,
screensavers, and fonts on the device.

### 5.1 How it ships

- Vendored at **26.10.28** (upstream tag `26.10.28`, commit `d53bb266`)
  in `platform/ios/seed/plugins/storefront.koplugin/`. Only the
  `storefront.koplugin/` subdirectory of the upstream repo is vendored
  (~13 MB); its `assets/`, `fonts/`, `tests/`, etc. trees are build-time
  material.
- It is **not** in `plugins/`, so it never loads from the read-only
  bundle. The bundle scripts copy `platform/ios/seed/` to `app/seed/`
  (after the Lua precompile step, so it stays plain source), and
  `ios_loader.m` copies each `app/seed/plugins/*.koplugin` into
  `Documents/plugins/` on launch **only if that folder doesn't exist yet**.
- From then on, the only copy is the writable one in `Documents/plugins`.
  Storefront updates itself in place there, and an app update never
  overwrites it. Deleting `Documents/plugins/storefront.koplugin` in the
  Files app restores the seed version on next launch.
- Storefront installs plugins to `Documents/plugins`, fonts to
  `Documents/fonts`, and patches to `Documents/patches`; all three are
  writable and read by KOReader (§4).

### 5.2 Updating the vendored seed

Bumping the seed only affects fresh installs (or a deleted copy), since
existing installs update themselves. Stable tags only; skip `*-beta`.

1. Replace `platform/ios/seed/plugins/storefront.koplugin/` with the
   `storefront.koplugin/` subdirectory of the upstream release tag.
2. Commit as `local: update storefront.koplugin seed to <tag>`, with
   the upstream tag and commit in the message.
3. On device, verify: catalog loads; install, update, and uninstall a
   pure-Lua plugin; install a font and select it in a book; installed
   items survive an app restart; Storefront's self-update succeeds.

### 5.3 Known iOS limitations

- **Native-library plugins**: entries containing `.so`/`.dylib` can be
  installed but won't load, because iOS only loads signed code from the
  bundle (§2.1). Upstream added support for updates with native
  libraries in `d6efebe5`. Follow-up: filter these out or mark them
  "unsupported on iOS".
- **Subprocess work**: Storefront's background catalog work (ETag
  persistence etc.) runs inline on iOS because `fork()` is unavailable.
  If refreshes freeze the UI noticeably, add a progress indicator or
  chunk the work behind a `KO_IOS` check.

## 6. iPhone Duo (foldable) support

Apple's first foldable, released 2026-10-23: a **5.4" outer** display
and a **7.6" inner** display, iOS 26/27, with Split View and dual-app
multitasking. Folding or unfolding moves the app between two displays
with different sizes, aspect ratios, and safe areas while it is running.

### 6.1 Requirements

1. **Live fold/unfold**: switching displays re-lays out the UI at the
   new size without a restart, in both the file manager and the reader
   (reflowable and paged documents), and keeps the reading position.
2. **Correct pixel size**: the framebuffer must be sized in *pixels*
   from the event that reports pixels. Today `device.lua` resizes on
   `SDL_EVENT_WINDOW_RESIZED`, whose `data1/data2` are in **points**.
   On iOS, handle `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED` instead (or
   convert points with the display scale) so the 7.6" ↔ 5.4" switch
   doesn't produce a ⅓-scale or clipped buffer.
3. **Safe area per display**: re-query insets after the switch. This
   already happens in `framebuffer:resize`, but needs on-device checks
   that `layoutIfNeeded` returns the new display's insets and not the
   old one's. The inner display may have no notch, only a crease.
4. **Per-display DPI**: KOReader's sizes (fonts, margins, touch targets)
   depend on screen DPI. The two displays may differ, so set DPI from
   the active `UIScreen` on every resize unless the user has set a
   `screen_dpi` override.
5. **Orientation**: the unfolded inner display is close to square;
   allow all four orientations on it. Rotation must work whether the
   app is started folded or unfolded.
6. **Multitasking**: `UIRequiresFullScreen = true` opts out of Split
   View. Keep it for the first release. Supporting Split View later
   means arbitrary window sizes, which (2) mostly covers, plus
   handling `UIRequiresFullScreen = false` on iPad as well.
7. **Hinge/crease**: no special layout at first. A possible follow-up
   is a "two-page spread" option for the unfolded display, reusing
   KOReader's existing dual-page mode for paged documents.

### 6.2 Implementation plan

1. Add an iOS branch in `frontend/device/sdl/device.lua` that resizes on
   `SDL_EVENT_WINDOW_PIXEL_SIZE_CHANGED` and ignores
   `WINDOW_RESIZED` when `KO_IOS=1`. Add debounce logic so a fold that
   fires several events only triggers one relayout.
2. Add `ko_ios_get_screen_dpi()` to `ios_filepicker.m`, or a new
   `ios_display.m`, returning the active screen's DPI. Apply it in the
   resize path through `Device:setScreenDPI` unless the user has an
   override.
3. Verify that `applyIOSSafeArea` reads the post-switch window. If the
   insets are stale, defer the resize by one runloop tick.
4. Make sure `RedrawCurrentPage` + `ScreenResize` keep the current
   position in CRE (reflowable) documents across a size change. This
   is already broadcast; it needs checking on device.
5. Test matrix (on device, since there is no Simulator support): launch
   folded / unfolded × open book (EPUB, PDF) / file manager /
   open dialog × fold / unfold / rotate × night mode on/off.

### 6.3 Acceptance criteria

- No black bars, clipping, or ⅓-scale UI after any fold/unfold/rotate.
- Taps land where drawn on both displays, including near the edges.
- EPUB and PDF reopen at the same position after a switch.
- Text size looks the same in physical size on both displays (DPI
  applied), unless the user has a DPI override.

## 8. Open questions

  is recreated, the lifecycle path (§3) has to rebuild the
  renderer/texture as well.
- Should the version in Storefront's catalog be stable-only on iOS, or
  follow the user's beta setting?
